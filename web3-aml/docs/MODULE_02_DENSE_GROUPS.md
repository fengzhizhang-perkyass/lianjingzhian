# 模块二：双数据集关联群组接入记录

更新：2026-10-30。当前实现将群组发现、搜索先验与群组证据接入双数据集“多跳关联追踪”，保留原有桥接、预算、真实边校验和路径去重。模型一的B3／SA-DCF、冻结输入和冻结评分不变。

## 数据与方法

比特币沿用822,942个已评分地址、2,784,344条有向关系；以太坊严格使用103,171个已评分地址及其3,228条真实诱导关系，不扩回原始模型上下文图的未评分地址。

算法来自此次模块二源代码包：在风险锚点附近收集局部节点，将地址拆成转出／转入角色，通过确定性双侧剥离寻找高目标值的有向二部稠密块，再筛选和去重。目标是 `m / sqrt(|U| × |V|)`，密度是 `m / (|U| × |V|)`。当前实现以堆维护候选最小度，168张随机图逐字段对照原始慢实现，验证选择结果等价。

该密度描述转出／转入角色之间的关系集中程度，可以包含汇聚或分发的星形结构，不表示任意两个成员之间都相互交易。结构分综合密度、成员冻结风险和风险锚点占比，仅用于安排搜索顺序，不是某个地址或整个群组的恶意概率。

配置位于 `config/tracing.yaml`。首次以包内的500个最高分候选锚点、半径2、单锚点最多2000节点、最少3成员／4边、最低密度0.2等参数构建；不读取标签选群组，也不把未命中索引解释为附近不存在其他群组。

当前索引：

| 数据集 | 群组数 | 成员地址覆盖 |
| --- | ---: | ---: |
| 比特币 | 59 | 4077 |

“成员地址覆盖”为索引涉及地址的去重数量，不能与多个群组的成员数简单相加混用。

## 构建与恢复

在当前运行包齐备的项目目录执行：

```bash
python scripts/prepare_v3_runtime.py --groups-only
python scripts/prepare_v3_runtime.py --groups-only --verify-only
```

独立构建入口为 `scripts/build_dense_group_index.py`；需要强制从相同来源重建时可使用其 `--force`。产物位于 `artifacts/datasets/<dataset_id>/current/dense_groups/<revision>/`，包含 `groups.json`、`memberships.json`和 `metadata.json`，活动指针为同级 `active.json`。

索引绑定数据集、数据指纹、当前有效风险修订、关系图修订、追踪范围、校准修订、构建配置及算法散列；读取时核验内容散列、成员、真实边、统计和冻结分数。文件缺失、结构损坏、算法或配置变化均不会静默套用旧索引，而是关闭可选群组能力，保留基础追踪。

准备群组后，显式准备流程会真实刷新长链示例。若只改了追踪／报告源码并需要刷新缓存：

```bash
python scripts/refresh_trace_examples_v4.py --dataset all
```

它会重放每个起点及参数并核验真实跳数与当前版本，不仅替换版本字段。当前比特币示例31／31／5跳，以太坊5／4／4跳。网页启动不训练或构建这些资产。

## 搜索与前台查看

正常追踪默认利用有效群组先验，可以调整候选顺序与路径排名，但不会提高低分连接地址的分数。原反向可达索引、低风险见证、预算共享、防环、观测关系展示和覆盖选路继续生效。

前台默认保留原追踪图；“发现关联群组”是只读证据查询，不重新追踪、不重新评分。工具栏为“适应画布—重置布局—发现关联群组—选择节点”。发现范围是起点及当前选中路径，展示结构分、角色密度、成员数、内部关系数和关联依据。

点击群组可完整加载原追踪图外的成员和内部真实关系。大结果分批读取至完成，显示实际加载数量；补充关系独立保存，不写回原始路径或搜索统计。

聚合由用户手动触发，一次只允许一个群组；切换时先还原前一个。聚合节点不冒充地址，没有地址风险概率；外部汇总连线保存底层有向关系，仅供展示。点击群组节点展开后恢复成员、方向和位置。地址选择、拖动、缩放及风险颜色继续可用。

## API契约

现有 `POST /api/traces`请求参数保持兼容，结果增加 `dense_group_guidance`、`suspicious_groups`和路径的 `dense_group_evidence`。活动群组索引修订进入结果版本，旧修订不能作为当前分析复用。

### 查询相关群组

`GET /api/traces/{trace_id}/groups?dataset_id=bitcoin&path_id=…`

- 不传 `path_id`时返回起点相关群组；传入时返回起点及这条已保存路径相关群组。
- 路径必须属于指定追踪结果，数据集及版本必须与当前活动服务一致。
- 返回 `enabled`、`status`、`revision`、`groups`以及上下文身份。
- 状态区分 `ready`、`missing`、`invalid`、`disabled`等；无匹配群组与索引失效不同。

### 加载完整群组

`GET /api/traces/{trace_id}/groups/{group_id}?dataset_id=bitcoin&path_id=…&offset=0&limit=500`

- 有路径参数时只允许起点及该路径相关群组；无路径参数时允许起点及任一原输出路径相关群组。
- 返回 `nodes`、`edges`、`summary`、`revision`及分页字段。
- `nodes`具有 `address_id`、精确 `risk_score`、`risk_level`、`is_scored:true`。
- `edges`具有 `src`、`dst`和真实来源 `evidence`；不会产生成员之间的虚构连边。
- 分页字段为 `offset`、`limit`、`total_nodes`、`total_edges`、`next_offset`、`has_more`、`complete`。
- 两个数组都用相同偏移分别切片，直到较长数组也加载完成。API允许每页1—1000项，不能只读第一页就宣称加载完整。

查询不会写入新的追踪快照。跨链或过期结果返回版本冲突；错误的路径／群组返回不存在；无效分页参数返回输入错误。

## 可信研判证据

当前报告链路是 `src/report/dataset_reporting.py`。报告自动匹配起点及前三条正文路径相关群组，不依赖用户点击发现、选中或聚合。完整相关群组快照保留在证据包中，正文最多展示5个并明确范围。

新增 `dense_group`及 `dense_group_coverage`事实，包括成员与关系数量、结构统计、路径关联和来源引用；以实际图和冻结风险重新校验。活动索引存在时，不能通过把两个启用标记改成false来省略应有证据。索引确实不可用时，报告仍正常生成并说明未纳入群组。

LLM继续组织已经核验的事实；不会将群组结构分当恶意概率、将聚合边当交易、将稠密关系直接认定为共同控制或连续资金流。公开报告不恢复SA-DCF融合权重。


真实浏览器脚本为 `scripts/check_dense_group_frontend.cjs`，需要已有的本机Playwright／Chrome；默认测试地址及结果目录见该脚本。辅助纯展示模型测试与真实链上案例区分，不用构造测试数据充当真实发现。

当前本地96组开关配对、192次追踪检查通过真实边、无环、预算及冻结评分一致性，但小样本中检查量和关系覆盖均没有观察到变化。此次可交付能力是群组证据和交互、默认群组先验及可核验搜索；不把旧包8.39%或11.54%的检查量下降当作当前系统收益，也不宣称识别准确率提高。

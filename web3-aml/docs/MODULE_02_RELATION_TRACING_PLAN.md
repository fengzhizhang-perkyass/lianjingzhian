# 模块二：资金关系链追踪——痛点、学术参考与轻量实验计划

记录日期：2026-10-11。状态：**历史初始设计快照**。后续已完成实现与实验，当前方案见 [模块二实现记录](MODULE_02_RELATION_TRACING.md)。PPR 经对照未进入默认方案，改为风险锚点可达见证。
本轮完成代码诊断、论文元数据/摘要检索、接口与实验路线设计。未安装新追踪算法，未宣称性能提升。
统一设计约束：[三个模块与三个创新](THREE_MODULE_INNOVATION_ALIGNMENT.md)。

## 1. 模块任务与数据能力

输入：Seed 地址、模块一预计算风险、有向地址关系图、搜索配置。
输出：值得进一步排查的真实有向关系路径、子图、搜索统计、保留理由和可引用证据。
公开 Actors 关系边缺少本任务所需的完整逐笔金额/时间，因此当前是资金关联关系链追踪。
不推断精确污染比例、金额守恒、严格时间连续资金流或真实主体控制关系。

## 2. 现有基线已经做了什么

代码：[beam_search.py](../src/tracing/beam_search.py)、[path_scorer.py](../src/tracing/path_scorer.py)。
默认深度 4、Beam 宽度 5、风险阈值 30、每节点最多 50 个下游、Top-10，检查环路。

```text
节点扩展分 = 0.75×地址风险 + 0.15×邻居平均风险 + 0.10×度数惩罚
路径分 = Seed之后各节点扩展分均值 × 长度衰减
```

风险先归一化。算法只沿 outgoing 方向，逐层收集保留路径并按路径序列去重。
邻居上限先按地址风险选候选，最终路径可能包含同一长路径的多个前缀。
这是现有行为，本身符合原 V1 设计；本轮寻找其可改善之处。

## 3. 从代码和案例确认的问题

### 3.1 逐节点门槛与关系链价值可能不一致

构造机制例子：`A(95) → B(10) → C(95)`。当前阈值 30 会在 B 截断，返回零路径。
这仅证明硬阈值机制如何工作；不是一条真实洗钱链，也不是新算法收益。
真实链上的低分节点是否值得保留，需要可达证据和同预算实验检验。

### 3.2 路径数量不等于新增信息量

默认未知高风险 Demo `1EVmeeBuxj5jzUitfAjAiSYZwM6A6owyFS` 当前返回 4 条路径：

- 2 条是其他保留路径的严格前缀，占 50%。
- 路径合计 8 次边出现，只有 4 条唯一有向边，重复出现占 50%。
- 折叠严格前缀后仅有 2 个最大路径序列；它们仍共享前段，不能称作两条独立资金链。

诊断覆盖九个预置 Demo。这是手选案例描述，不能外推全图平均冗余。
来源：[baseline_diagnosis.json](../artifacts/experiments/tracing_v2_planning/baseline_diagnosis.json)。

### 3.3 Seed 关联性、预算与度数惩罚需要分开检查

现有节点扩展分不含单独的 Seed 个性化关联项，局部高风险可能挤占其他分支。
度数惩罚用于排序，不意味着高连接节点正常；可能经过高连接结构的路径是否被忽略需实验。
目前 Beam 与邻居上限约束候选，但未来加入 PPR/前瞻后，必须统计这些额外访问，不能假称成本相同。

## 5. 核心候选创新及其三个机制

候选名称：**Seed 关联与风险覆盖联合驱动的预算化路径追踪**。
一个主问题：在固定搜索与复核预算下，保留更多具有调查价值、重复更少的真实关系证据。
以下三个机制共同支持这个问题，最终是否保留由开发实验决定。

### 5.1 Seed 个性化相关性

参考 TRacer/PPR，候选基础形式：

```text
p = restart × e_seed + (1-restart) × P_out^T × p
```

`P_out` 来自真实 outgoing 邻接，悬空节点的质量按统一规则回到 Seed。
拟用有限残差传播或局部诱导图近似；预算耗尽则停止并记录残余，不能声称得到精确全图 PPR。
相关性是 Seed 图关联的近似量，不是地址非法概率。它与模块一风险共同参与候选排序。
先实现无权有向版本，不制造缺失金额和交易时间。

### 5.2 有见证、有预算的低分桥接

拟允许有限低分中间节点，当真实下游的有限前瞻发现满足门槛的节点/路径时，保留继续搜索机会。

- 第一版从最多连续 1 个低分节点开始，必须保留真实可达见证。
- 前瞻只沿真实边，不越过最大深度；所有邻居检查计入同一预算。
- 临时桥接候选必须继续沿见证边实际扩展，最终输出不凭前瞻补造路径。
- 地址原始风险保持不变；输出标记低分中间连接及保留理由，不推断其洗钱作用。
- 存在桥接代价、候选配额和全局预算，避免全局降低阈值导致范围失控。

必须与“直接降低阈值”的基线比较，验证改进是否超出宽松搜索的作用。

### 5.3 路径多样性与新增覆盖

参考 DBS，在搜索时检查分支/有向边重叠；参考 MMR 和预算覆盖，在最终展示中贪心选择新增证据。
候选重排形式可为：

```text
选择收益 = 路径基础效用 + 新增风险加权节点/边覆盖 - 已选路径重叠惩罚
```

具体权重由开发协议确定；这是候选目标，不是经过验证的性能公式。
Seed 从覆盖奖励中排除，避免所有路径共同的起点刷分；覆盖按唯一节点/边计数，重复不会反复奖励。
严格前缀可以折叠为长路径的证据记录，保留其分数与引用；若短路径有独立终点价值，应允许保留并注明原因。
折叠前缀和降低重复只是展示改进，不能单独证明找到了更多真实相关分支。
包含局部搜索、桥接和重叠惩罚的完整算法不声称具有单调次模近似保证。

## 6. 与模块一衔接及允许的调整

第一轮冻结当前 V2.0 风险模型、风险表与 revision，仅改变搜索算法。
直接输入校准综合风险、地址索引、有向图，评分依据可作为输出证据引用。

| 模块一字段/产物 | 模块二用途 | 限制 |
|---|---|---|
| `overall_risk_score` | 风险引导、锚点门槛、覆盖权重 | 保留原始分，不重新包装成路径概率 |
| `risk_level` | 图颜色与证据展示 | 不因桥接入选自动升级等级 |
| 评分 revision / 数据指纹 | 绑定版本与缓存 | 拒绝不同数据或评分混用 |
| `scoring_analysis` | 引用地址评分依据 | 不重复训练评分，不将 TreeSHAP 当因果关系 |
| 可选结构上下文 | 度数、上下游计数等搜索上下文 | 使用真实图，不引入真实标签 |

若字段不足，可增加兼容 Adapter：明确偏离分别名、暴露已有结构统计、输出版本化上下文。
单组诊断分歧未做不确定性校准，暂不把分歧用于“置信桥接”。
如果确需重训模块一，单独记录新版本并同时比较冻结评分与新评分，避免混淆两个模块的贡献。

## 7. 与模块三衔接的拟新增输出

保留现有字段与排序，新增可选 `method`、`provenance`、`search_budget`、`selection_analysis`。
每条路径保留 `nodes`、`node_risks`、`hop_count`、`path_score`，增加稳定 `path_id` 和可引用 `evidence_id`。

```text
provenance
  dataset_fingerprint / risk_revision / tracing_revision / config_hash
search_budget
  configured_limit / actual_edge_inspections / elapsed_ms / stop_reason
top_paths[*]
  path_id / nodes / node_risks / path_score / score_components
  bridge_nodes / bridge_witness / source_references
selection_analysis
  unique_nodes / unique_edges / overlap / prefix_folding / marginal_gain
```

上述是拟议契约，当前旧输出尚无这些新增字段。正式实现需定义类型、单位与版本，不能直接依赖未实现字段。
桥接理由、剪枝和停止条件采用确定性代码，例如 `RISK_BELOW_THRESHOLD`、`BUDGET_EXHAUSTED`、`CYCLE_BLOCKED`、`BRIDGE_WITNESS_FOUND`。
人类可读说明由证据模板映射，不让 LLM 自行猜搜索过程。
金额和逐笔时间缺失时明确 unavailable，报告只说明有向关系与搜索优先级。

## 8. 同预算对照与消融计划

| 实验 | 作用 |
|---|---|
| 有界 BFS | 对比范围扩展与风险引导 |
| 当前 Risk-Guided Beam | 冻结原始基线 |
| 更低硬阈值 Beam | 检查收益是否仅来自放宽筛选 |
| 原 Beam + 前缀折叠/MMR | 分离展示重排收益 |
| Seed PPR 引导 Beam | 检验个性化相关性 |
| PPR + 受约束桥接 | 检验断点跨越 |
| 完整候选 | 加入搜索多样性与覆盖选择 |
| 去 PPR / 去桥接 / 去多样性 | 三个组件各自的额外价值 |

同一组 Seed、图快照、评分 revision、最大深度、真实边访问上限、最终路径数与硬件。
PPR、候选前瞻、邻居遍历及重排耗时均计入成本。分别报告冷加载与服务已加载后的搜索耗时。
对不确定 tie 使用固定规则/种子；记录实际访问量，而非只写配置上限。
权重/阈值先在开发图或验证 Seed 选择，冻结后评估；不靠展示案例选最优算法。

## 9. 评价指标与真值边界

### 9.1 构造机制图

构造已知 planted relation paths，覆盖低分桥、平行分支、共同前缀、高连接节点、循环、死端和噪声边。
独立变化风险噪声和图结构，避免只用与新公式完全一致的样例。
报告植入目标节点/路径恢复、分支覆盖、噪声扩展与预算；称为构造机制验证，不称为真实 AML 链路准确率。

### 9.2 真实地址图

当前没有金额级洗钱路径真值，分别报告：

- 标签无关：路径边有效性、无环、预算合规、唯一边/节点覆盖、前缀率、平均重叠、耗时 p50/p95。
- 模型代理：风险加权覆盖、发现预测高风险节点的数量，明确由模块一预测定义。
- 标签辅助离线指标：预定义 Seed 的预算内已知 illicit 节点命中/覆盖，标签只用于评估，不输入搜索。

以上都不等于真实资金链 Precision/Recall。unknown 不按 licit 计数；未知路径不判为错误。
更长、更多、更高分的路径不自动更优，输出路径数量还受前缀折叠影响。
若有条件接入含明确链路证据的公开案例，另建外部案例集并核实证据范围，不能移用异构跨链数据的任务标签。

## 10. 阶段安排与通过条件

1. **论文深化与设计冻结**：先深读 TRacer 和 MMR/DBS 核心方法，标出借鉴、省略和新增部分。
2. **机制与接口实现**：配置化、预算计数、版本绑定、搜索理由、兼容旧输出；测试方向/循环/桥接/真边。
3. **开发对照**：同预算实现对照，保留不利结果；先检查较低阈值能否达到相同收益。
4. **消融与冻结评估**：检查每个机制是否贡献覆盖/恢复收益，成本与噪声是否可接受。
5. **闭环验收**：模块一查表 → 新追踪 → Evidence → 模板/LLM 接口 → UI，文档与演示同步。

只有当冻结评估支持额外收益、成本可控且模块接口验收通过，才把候选命名改为“当前创新方案”。
若复杂组件没有开发优势，保留更简单有效的组合，不为了保留论文名增加复杂度。
